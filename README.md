# Sales Manager FIRST — Run Evidence Adapter · SFA-P46

Реализация задания **SFA-P46-RUN-EVIDENCE R1**, комплект H2-RU-CHECK.

Компонент `build_run_evidence` связывает переданный отчёт о тестах с описанием команды запуска, точными байтами тестовых файлов и выводом. Он проверяет согласованность данных и формирует SHA-256 и снимок идентичности для принятого компонента P47.

Это продолжение [предыдущего адаптера unittest](https://github.com/dimitry8st-prog/Sales-Manager-FIRST-Unittest-Evidence-Adapter-SFA-P46). Его `RecordingResult` включён в выданный комплект как защищённая зависимость. Новый результат находится в отдельном `command_evidence.py`.

## Назначение компонентов

| Компонент | Ответственность |
|---|---|
| P23 · `run_suite` | Выполняет переданный доверенный набор тестов и возвращает отчёт с выводом |
| P46 · `RecordingResult` | Записывает фактические callbacks unittest как PASS, FAIL, ERROR или SKIP |
| Новый · `build_run_evidence` | Проверяет отчёт, связывает данные хешами и сохраняет точные байты stdout/stderr |
| P47 · `assess_applicability` | Сравнивает снимки и оценивает применимость результатов после изменений |

Хеш описывает полученные байты. Подлинность отчёта, происхождение команды и факт её выполнения обеспечивает контролируемый внешний исполнитель. Сам адаптер команд не выполняет и файлы не читает.

## Проверка на Windows

Нужен Python 3.12. Сторонние пакеты не требуются. Команды выполняются из корня распакованного задания:

```console
git clone https://github.com/dimitry8st-prog/Sales-Manager-FIRST-Run-Evidence-Adapter-SFA-P46.git
cd Sales-Manager-FIRST-Run-Evidence-Adapter-SFA-P46/04_Dmitry_SFA_P46_RUN_EVIDENCE
py -3.12 --version
py -3.12 -B CHECK_PACKAGE.py
py -3.12 -B RUN_PUBLIC_TESTS.py
py -3.12 -B RUN_CANDIDATE_TESTS.py
```

В Linux/macOS используется `python3.12` вместо `py -3.12`. Все три команды должны завершиться кодом 0. Пустой набор, пропуски и ожидаемые неудачи верхнего набора тестов не принимаются. Намеренные FAIL/ERROR/SKIP внутри проверяемых учебных наборов подтверждаются внешними успешными тестами.

Проверка целостности охватывает 17 защищённых файлов. Их содержимое, публичные тесты и три принятые зависимости сохраняются побайтно. `.gitattributes` отключает автоматическое преобразование переводов строк при работе через Git.

## Существенные правила

- Конфигурация проверяется конструктором принятого `RecordingResult`; только его `RecordingError` переводится в `INVALID_INPUT` с сохранением причины.
- Хеш команды включает `argv`, `cwd`, `interpreter`; её ключ в хеш не входит.
- Хеш отчёта охватывает полный отчёт с исходным порядком записей. Unicode и CRLF не нормализуются.
- Вывод ограничен 4 МиБ на поток; один тестовый артефакт — 4 МиБ, все артефакты вместе — 8 МиБ.
- После failfast отсутствующие результаты не добавляются. Пустой запуск не означает общий PASS.
- Снимок содержит COMMAND и TEST. Одинаковых снимков только этих двух измерений недостаточно для MATCH в P47: нужны также SOURCE, SCHEMA, CONFIG, DEPENDENCY, RUNTIME и полный перечень зависимостей проверяемого случая.
- `external_effect_authorized` и `gate_acceptance` всегда равны `False`.

## Сдача и граница подключения

ZIP сохраняет единственную исходную корневую папку `04_Dmitry_SFA_P46_RUN_EVIDENCE/`. Внутри находятся реализация, собственные тесты и весь каталог `return/`: описание, отчёт, патч, контрольные суммы, полные журналы трёх команд и предложение подключения/восстановления.

Из корня репозитория сборка и проверка архива воспроизводятся инструментами в [tools/](tools/):

```console
py -3.12 -B tools/build_return.py
py -3.12 -B tools/verify_return.py
```

Первая команда заново выполняет проверки и записывает фактические журналы; вторая
проверяет ZIP после распаковки в чистую папку и восстанавливает изменения патчем.
Для проверки применения патча требуется установленный Git. Сборка обновляет
времена и журналы в новом архиве; SHA-256 исходного сданного ZIP указан в его
соседнем файле `*.validation.json`.

Рабочее подключение выполняет центральный интегратор после приёмки. Общая регрессия и приёмка Sales First остаются отдельными этапами. БД, миграции, запуск служб и внешние отправки в это задание не входят.

# Предложение подключения и восстановления

Статус: **компонент проверен отдельно; рабочая интеграция NOT_CONNECTED**.
Это предложение для центрального интегратора после приёмки точного возврата,
а не выполненная установка. Продуктовая регрессия и приёмка Sales First открыты.

## До установки

1. Проверить SHA-256 переданного ZIP, исходного комплекта, защищённых зависимостей
   и изменённых файлов по манифестам. Повторить три команды README на Python 3.12
   из корня распакованного пакета; изучить исходные сырые журналы.
2. Повторно сверить рабочие исходники, актуальный реестр компонентов и разрешённые
   области изменений. Убедиться, что новый `audit_release/command_evidence.py`
   отсутствует. Если файл уже существует или зависимости отличаются от закреплённых
   хешей, остановить установку и согласовать совместимость с владельцами.
3. Сохранить исходный перечень файлов, их хеши и фактические пути импорта.
   Изменения общей сборки проводит один интегратор последовательно.

## Последовательное подключение

1. Установить только новый `audit_release/command_evidence.py` и необходимые
   собственные тесты. Не подменять уже принятые `unittest_evidence.py`,
   `unittest_runner.py`, `test_applicability.py` файлами из пакета.
2. Проверить фактический путь импорта `audit_release.command_evidence.__file__`,
   хеш установленного модуля и точную сигнатуру `build_run_evidence`.
3. Передавать report только от контролируемого P23, а команду/артефакты — от
   доверенного вызывающего кода. Новый адаптер не выполняет команду и не является
   песочницей. Связь переданных байтов с реальным запуском обеспечивает вызывающий.
4. Проверить цепочку P23 → RecordingResult → build_run_evidence → P47, точные raw
   stdout/stderr и соответствие хешей. Полные журналы архивирует вызывающий код.
5. Для полной оценки применимости P47 отдельно обеспечить достоверные
   SOURCE/SCHEMA/CONFIG/DEPENDENCY/RUNTIME и описание влияния проверок.
   Только COMMAND/TEST при равенстве дают UNKNOWN. Известное релевантное изменение
   имеет приоритет и может дать CHANGED_AFFECTED даже при неполном снимке.
6. Выполнить затронутые проверки рабочей сборки и согласованную общую регрессию.
   Зафиксировать команды, версии, exit codes и действительные ограничения.
   Компонентный PASS этого возврата не заменяет продуктовую приёмку.

## Восстановление

1. Остановить дальнейшее подключение и сверить идентичность добавленных файлов
   с хешами точно установленной версии.
2. Удалить только добавленный модуль и необходимые добавленные тесты, если их
   идентичность совпадает. При чужих изменениях не удалять и не переписывать файлы
   автоматически — согласовать действие с их владельцем.
3. Сверить исходный перечень/хеши файлов и пути импорта; повторить исходные проверки.
   Соседние принятые компоненты при этой процедуре не меняются.

БД, миграции, службы, активация обработчиков и внешние отправки в пакет не входят.
Оба флага `external_effect_authorized` и `gate_acceptance` остаются False.

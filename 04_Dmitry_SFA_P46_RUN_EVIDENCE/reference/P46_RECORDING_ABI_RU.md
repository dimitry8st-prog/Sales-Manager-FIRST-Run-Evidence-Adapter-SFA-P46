# Контракт SFA-P46-UNITTEST-ADAPTER R1

## Область реализации

Python 3.12, только стандартная библиотека. Модуль `audit_release.unittest_evidence` экспортирует `RecordingError(ValueError)` и `RecordingResult(unittest.TestResult)`.

`RecordingError.code` — точная строка нормативного кода; `str(error)==error.code`. Во входные данные текста ошибки не включать. Дополнительной защиты свойства от присваивания контракт не требует.

Программный интерфейс: `RecordingResult(*, release_id, bindings, attempt=1)`, стандартные обратные вызовы `unittest.TestResult`, метод `records() -> list[dict]`.

Адаптер сам не загружает и не запускает тесты. Доверенный вызывающий код отдельно выполняет `suite.run(result)`. Адаптер записывает фактически полученные события, не разбирает стандартный вывод (`stdout`) и не принимает заявленный пользователем статус вместо события. Доверие к источнику запуска и пригодность доказательств для рабочего релиза устанавливает интегратор вне этого компонента.

## Конфигурация до запуска

Под точным типом понимается `type(x) is ...`, подклассы запрещены. Идентификаторы релиза/набора/случая — точные `str` по полному ASCII-шаблону `[A-Za-z0-9_.-]{1,128}`.

- `release_id` — такой идентификатор.
- `attempt` — точный `int >= 1`, `bool` недопустим.
- `bindings` — точный `list` из 0..10000 элементов. Каждый элемент — точный `dict` ровно с точными строковыми ключами `test_id`, `suite_id`, `case_id`.
- `test_id` — точный `str` длиной 1..512 символов, без любого `str.isspace()`, кодов U+0000..U+001F/U+007F и суррогатов. Сравнение точное, без нормализации. `suite_id` и `case_id` — идентификаторы указанного выше ASCII-формата.
- `test_id` уникальны. Пары `(suite_id,case_id)` также уникальны; один случай не может представлять несколько методов или подтестов.

При любом нарушении конструктор поднимает `RecordingError("INVALID_CONFIGURATION")`, не сохраняет ссылок на изменяемые контейнеры входа и не вызывает тесты. Для конфигурации не нужен план F1-27: соответствие её пар принятому плану проверяет интегратор перед запуском. Адаптер не придумывает план или новые идентификаторы.

## Цикл выполнения и запрет ложного успеха

Объект работает последовательно, без параллельных обратных вызовов. Для каждого разрешённого `test_id` допустим ровно один цикл на экземпляр адаптера:

`startTest(test)` → ровно один поддержанный итог → `stopTest(test)`.

`test.id()` должен вернуть точный разрешённый `test_id`; при обычном `Exception` из `id()` фиксируется нарушение выполнения; `MemoryError`, `KeyboardInterrupt` и `SystemExit` должны распространяться без подавления. Не вызывать `repr/str` теста или исключения для формирования `records`. Один идентификатор может быть представлен любым экземпляром `TestCase` с этим идентификатором; проверяется именно идентификатор и цикл, а не адрес объекта. Проверка идентификатора не предоставляет тесту доверия.

Одновременно активен максимум один идентификатор. Повторное выполнение уже начатого идентификатора, неизвестный идентификатор, итог без соответствующего старта, повтор итога, остановка без старта или без итога, старт следующего теста до остановки предыдущего — нарушение. Метод `records()` при активном незавершённом тесте также фиксирует нарушение.

Поддержанные итоги:

| Обратный вызов | status | exit_code | skip_count |
|---|---|---:|---:|
| `addSuccess(test)` | PASS | 0 | 0 |
| `addFailure(test, err)` | FAIL | 1 | 0 |
| `addError(test, err)` | ERROR | 1 | 0 |
| `addSkip(test, reason)` | SKIP | 0 | 1 |

`exit_code` здесь — **нормализованный код отдельного случая**, а не фактический код процесса. Трассировка исключения и причина пропуска в `records` не добавляются. Стандартные поля и поведение `TestResult`, включая `testsRun`, `failures`, `errors`, `skipped`, `shouldStop`, `failfast`, должны сохраняться стандартными вызовами родительских методов через `super`. Настройка `failfast=True` и `stop()` разрешены; неисполненные после остановки привязки не превращаются в PASS.

Любой вызов `addSubTest`, в том числе успешный (`err=None`), `addExpectedFailure`, `addUnexpectedSuccess` — неподдержанный итог: фиксируется нарушение. Синтетическая ошибка `setUpClass/tearDownClass` обычно имеет неизвестный идентификатор и также не может стать записью случайно выбранного теста. Этот этап не поддерживает такие конструкции: вызывающий раннер должен сохранить диагностические логи, а интеграция не должна выдавать частичный набор за полный результат.

Любое нарушение цикла/итога/идентификатора ставит необратимый признак недействительного выполнения на этом объекте. Ошибочные обратные вызовы не поднимают `RecordingError` непосредственно, чтобы стандартное завершение тестов и освобождение ресурсов могли закончиться; `records()` после этого всегда поднимает `RecordingError("INVALID_EXECUTION")` и не возвращает частичные записи. Не поглощать `KeyboardInterrupt`, `SystemExit`, `MemoryError` и неожиданные ошибки собственной реализации. Параметр `err` поддержанных вызовов `addFailure`/`addError` передаётся соответствующему родительскому методу через `super`; его внутреннюю валидность определяет стандартный `unittest`; адаптер не обязан исправлять вызовы с произвольным некорректным `err`.

Глобальные `startTestRun/stopTestRun` не обязательны для `suite.run(result)` и не меняют записи. Объект не сбрасывается. Повторный запуск уже выполненного идентификатора на том же объекте — ошибка; новая попытка требует нового экземпляра с явным `attempt`.

## Выход

Если нарушение не зафиксировано и нет активного теста, `records()` возвращает новые независимые контейнеры, отсортированные по `(suite_id,case_id)` обычным сравнением строк Python. Каждый элемент имеет ровно семь полей:

```json
{"release_id":"release-1","suite_id":"unit","case_id":"case-1","attempt":1,"status":"PASS","exit_code":0,"skip_count":0}
```

Включаются только полностью завершённые поддержанные случаи. Привязки без событий отсутствуют: F1-27 впоследствии определяет их как NOT_RUN по своему плану. Ноль выполненных тестов даёт `[]`, а не общий PASS. `records()` не завершает и не запечатывает объект: после снимка можно выполнить иной ещё не начатый привязанный идентификатор. Каждый снимок независим от конфигурации, внутреннего состояния, других снимков и других экземпляров.

Не возвращать общую сводку, готовность релиза, исходные исключения, исходную полезную нагрузку, команды или флаги авторизации. Не добавлять собственный интеграционный или файловый ввод-вывод, сеть, БД, переменные окружения, часы, случайность, дочерние процессы или глобальное хранилище входов. Стандартная диагностика `unittest` через обязательные вызовы родительских методов разрешена: форматирование трассировки исключений может читать строки локальных исходников через стандартный модуль `linecache`; это не разрешает адаптеру собственное чтение данных, запись файлов или сеть. Хранение стандартных диагностических полей `TestResult` допустимо и не является частью возвращаемого списка `records`. Побочные эффекты самих доверенных экземпляров `TestCase` не являются операциями адаптера; раннер не заявляется песочницей. Мутации конфигурации вызывающим кодом после конструктора не меняют привязки адаптера.

## Обязательные собственные проверки

Все формы, границы значений и подклассы; повторяющиеся привязки; точные ошибки; полный поддерживаемый цикл; фактические провалы, ошибки и пропуски внутри `TestCase`; смешанный набор; немедленная остановка по `failfast` и неисполненные случаи; успешные и ошибочные подтесты; `addExpectedFailure` и `addUnexpectedSuccess`; ошибки подготовки и завершения класса; неизвестные идентификаторы и ошибки метода `id`; повторяющиеся, пропущенные и переставленные обратные вызовы; пустой набор; несколько снимков и попыток; независимость контейнеров; отсутствие собственных побочных эффектов. Публичные тесты не исчерпывают контракт.

# SFA-P46-RUN-EVIDENCE R1 — новый нормативный ABI
## Результат и реальный потребитель
Добавьте `audit_release/command_evidence.py`, экспорт `RunEvidenceError(ValueError)` с точными `code`/str и `build_run_evidence(report, *, release_id, bindings, attempt=1, command, test_artifacts) -> dict`.
Это новый адаптер фактического отчёта P23: сохраняет записи F127, связывает содержимое отчёта/логов и идентичность байтов COMMAND/TEST для принятого `audit_release.test_applicability.assess_applicability`. Новая оболочка задаётся этим ТЗ; P47 ABI не меняется. Не переписывать P46 RecordingResult и исполнитель P23, не создавать новую политику F127 или доверенного владельца источников.

## Точная проверка до результата
Во всех ниже перечисленных контейнерах требуются точные типы (`type(x) is ...`), ключи точные str и ровно указанный набор. Любой неверный вход даёт `RunEvidenceError('INVALID_INPUT')`; не включать содержимое входа в ошибку.

`release_id`, `bindings`, `attempt` проверьте созданием принятого `RecordingResult` (он не запускается). RecordingError переводится в INVALID_INPUT с исходным исключением в `__cause__`; другие неожиданные ошибки не маскируются. `report.records` — точный `list`, от 0 до 10000 записей включительно. `bindings` не изменять.

`report` ровно `schema_version,records,counts,stdout,stderr`, schema_version точно `FIRST_OFFLINE_UNITTEST_RUN_V1`. stdout/stderr — str, каждый не больше 4194304 байт в строгом UTF-8; суррогаты запрещены, переводы строк/Unicode не нормализовать. counts ровно tests_run/failures/errors/skips, точные неотрицательные int (не bool).
Каждая запись record — dict ровно release_id/suite_id/case_id/attempt/status/exit_code/skip_count. release_id/attempt точно равны конфигурации; suite_id/case_id входят в bindings, пара уникальна. Для статусов точные тройки:

| status | exit_code | skip_count |
|---|---:|---:|
| PASS | 0 | 0 |
| FAIL | 1 | 0 |
| ERROR | 1 | 0 |
| SKIP | 0 | 1 |

Коды/skip_count точные int; status точный str. counts.tests_run == len(records); остальные counts точно числам соответствующих FAIL/ERROR/SKIP. Отсутствующие bindings допустимы (failfast), их не дорисовывать. Нормализованный код записи не именовать фактическим кодом завершения процесса. Ноль records не даёт PASS.

`command` ровно key/argv/cwd/interpreter. key — ключ артефакта P47: ASCII 1..2048, сегменты `[A-Za-z0-9_.-]+`, не `.`, не `..`, без точки в конце сегмента и без зарезервированных базовых имён Windows CON/PRN/AUX/NUL/COM1..9/LPT1..9. argv — list 1..256 непустых str, каждое <=4096 символов; cwd/interpreter — непустые str <=4096. Для строк argv/cwd/interpreter запрет U+0000..U+001F/U+007F/суррогатов; Unicode сохраняется точно. Вызов команд не выполняется.

`test_artifacts` — list 0..256 dict ровно key/content. key по тому же правилу, уникален без учёта ASCII-регистра внутри kind TEST; content — bytes, до 4194304 каждый и до 8388608 суммарно. Подклассы bytes и bytearray запрещены. COMMAND и TEST могут иметь одинаковый key, поскольку kind различается.

## Хеширование и точный выход
Канонические байты описания command — `json.dumps({'argv':...,'cwd':...,'interpreter':...},ensure_ascii=False,sort_keys=True,separators=(',',':'),allow_nan=False).encode('utf-8')`. key в хеш command не входит. Канонические байты report — тот же JSON-алгоритм для полного принятого report, порядок списка records сохраняется. SHA256 — строка шестнадцатеричных цифр в нижнем регистре. Стандартный hashlib/json разрешён.

Вернуть ровно:
- schema_version=`FIRST_RUN_EVIDENCE_ENVELOPE_V1`;
- records: новые независимые записи F127 в исходном порядке, точные статусы/коды/attempt;
- report_sha256: хеш канонических байтов report;
- identity_snapshot: `{'schema_version':'FIRST_TEST_IDENTITY_SNAPSHOT_V1','artifacts':[...entries...]}`. Одна запись COMMAND с key в нижнем ASCII-регистре и хеш канонических байтов command; записи TEST с key в нижнем ASCII-регистре и хеш точного content. элементы сортировать `(kind,key)`, каждый ровно kind/key/sha256. Этот объект напрямую принимает P47 `assess_applicability`; он описывает только COMMAND/TEST, остальные пять измерений вызывающий код добавляет самостоятельно; без них результат UNKNOWN, не MATCH.
- raw_outputs: ровно stdout/stderr; каждый dict ровно content/sha256/size_bytes. content — точные байты UTF-8 соответствующей строки report; хеш и размер фактических байтов. Эти байты вызывающий код может архивировать; адаптер файлов не пишет.
- external_effect_authorized=False; gate_acceptance=False.

Контейнеры не зависят от входных контейнеров/предыдущих вызовов. Нельзя хранить входы глобально. Не выводить общий PASS, готовность, завершение плана или политику выбора последней попытки.

## Доверие и граница
Команду, интерпретатор и артефакты передаёт проверенный внешний вызывающий код: хеш подтверждает только переданные байты, не факт их исполнения/происхождение/подпись. Происхождение исходников, схемы, конфигурации, среды выполнения и зависимостей остаётся у их владельцев. Сам report должен поступать из контролируемого исполнителя P23: адаптер проверяет форму/внутреннюю согласованность, не отличает поддельный внутренне согласованный report от реального запуска. Не называть его удостоверением фактического выполнения. Полные неизменённые журналы и подтверждение интеграции сохраняет вызывающий код; никаких операций ввода-вывода, сети, чтения окружения или системного времени, запуска отдельных процессов или вывода здесь нет.

Собственные проверки: реальный отчёт P23→P46, все четыре статуса, отсутствующие bindings после failfast, пустой report; ошибочные типы/ключи/лимиты/подклассы; bool/attempt/release/неизвестная пара/повтор/несовпадение счётчиков; Unicode/CRLF/суррогаты; хеш канонических command/report, точные байты и отсутствие нормализации; переходы по key через . или ../зарезервированные имена Windows/совпадения без учёта регистра; лимиты байтов; неизменность входов/независимость выходного результата; реальный P47 принимает снимок, UNKNOWN без пяти измерений, MATCH с полными измерениями и CHANGED_AFFECTED после изменения байтов command/test. Публичный набор не исчерпывает контракт.

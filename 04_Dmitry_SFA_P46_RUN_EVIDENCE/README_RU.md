# Дмитрий — SFA-P46-RUN-EVIDENCE R1

## Что разработать
Привязка отчёта о проверках к описанию команды и точным байтам артефактов.

Изменяемый файл: `source/audit_release/command_evidence.py`.

Входы: Отчёт P23, release_id, bindings, attempt, описание command и test_artifacts; ограничения и ошибки — в CONTRACT_RU.md.

Результат: FIRST_RUN_EVIDENCE_ENVELOPE_V1: записи F127, хеш отчёта, снимок COMMAND/TEST и точные байты вывода. Снимок напрямую принимает P47; адаптер не удостоверяет происхождение отчёта.

Точный нормативный контракт — [CONTRACT_RU.md](CONTRACT_RU.md). Сначала прочитайте его целиком, затем INTEGRATION_RU.md и RETURN_RU.md. Не ограничивайтесь публичными тестами: они не перечисляют все обязательные требования.

## Среда и запуск
Нужен Python 3.12 со стандартной библиотекой. Устанавливать сторонние пакеты для этого задания не требуется. Закреплённые исходные зависимости включены в соседние защищённые файлы `source/`; папка `reference/` содержит русские описания принятого API. Изменяемым в `source/` остаётся только целевой файл, прямо указанный в задании; рабочая БД, сетевой доступ к проекту и доступ к рабочей установке для разработки этого компонента не нужны. Запускайте команды из корня полностью распакованного задания, а не из папки `source/`, `solution/` или `reference/`.

Ниже команды Windows с явным Python 3.12. В Linux/macOS замените `py -3.12` на `python3.12`; остальные аргументы сохраните. Укажите точную версию использованного интерпретатора в отчёте.

```console
py -3.12 CHECK_PACKAGE.py
py -3.12 RUN_PUBLIC_TESTS.py
py -3.12 RUN_CANDIDATE_TESTS.py
```

## Как понимать исходный результат
`CHECK_PACKAGE.py` должен завершиться с кодом 0: он проверяет целостность защищённых файлов. В целевом файле передан каркас, а не готовая реализация. Поэтому до разработки функциональные публичные проверки завершаются ненулевым кодом с `IMPLEMENTATION_REQUIRED`; это ожидаемый отказ, а не успешная приёмка. Пустой набор собственных тестов тоже не принимается.

Реализуйте `source/audit_release/command_evidence.py`, добавьте содержательные собственные тесты `candidate_tests/test_*.py` и повторите команды. После разработки обязательные проверки должны проходить без пропусков и ожидаемых неудач. Не изменяйте защищённые тесты, зависимости или проверяющие программы ради успешного результата.
